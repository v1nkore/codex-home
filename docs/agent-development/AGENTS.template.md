# Правила разработки с агентом

Адаптировать под репозиторий: указать реальные команды сборки и тестов, доменные документы, владельцев и действующие ограничения. Удалить эту вводную строку после переноса в корневой `AGENTS.md`.

## Перед изменением

1. Прочитай актуальную задачу, затронутый код и проектные правила. Для изменения поведения согласуй проверяемые критерии приёмки до реализации; используй [контракт задачи](TASK.template.md).
2. Выдели затронутые инварианты, внешние контракты, данные и сценарии отказа. Если требование допускает разные последствия для пользователя или данных, изложи варианты ответственному разработчику и дождись решения.

## Реализация и проверка

3. Делай изменение в пределах задачи. Отдельно обозначай необходимую сопутствующую правку и её причину.
4. Проверь поведение тестами на уровне, который способен обнаружить ошибку. Для изменений денег, документов, прав и данных включи применимые сценарии повторов, конкурентности, таймаутов, частичного сбоя и миграции.
5. Запусти доступные локальные проверки. Передай человеку: diff, commit или состояние рабочего дерева, результаты проверок, непроверенное, затронутые контракты и риски. После любого изменения кода повтори затронутые проверки.

## Граница самостоятельности

Готовность агента означает `ожидает принятия`, а не `принято`. Решение о выпуске и изменениях критичных данных принимает ответственный человек по правилам проекта. Работай только с доступами и средой, выданными для задачи.

Для независимой проверки критичного diff используй $critical-change-review. Результаты ревью сопоставляются с исходной задачей и актуальным commit.
