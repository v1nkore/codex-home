# Codex home

Переносимый снимок публичной части настроек и skills Codex. Личные правила и доступы в него не входят.

## Что хранится

- `AGENTS.md` — отобранные общие правила; личный глобальный файл может содержать дополнительные правила.
- `config.portable.toml` — безопасная переносимая часть настроек.
- `skills/` — зафиксированная копия всех установленных пользовательских и curated skills.
- `docs/agent-development/` — переносимый процесс разработки с агентами: контракт задачи, правила и проверка качества ревью.
- `sources/` — происхождение и лицензии сторонних наборов skills.
- `install.sh` — восстановление на новом устройстве с резервными копиями.
- `scripts/sync-from-home.sh` — локальное обновление переносимых настроек и skills из текущего `~/.codex`.
- `scripts/test-install-and-sync.sh` — проверка установки и синхронизации на временных данных.

Системные skills из `~/.codex/skills/.system` не копируются: они устанавливаются и обновляются самим Codex.

## Восстановление на новом Mac

Нужны Git и Bash. Сначала установите и хотя бы один раз запустите Codex, затем просмотрите `AGENTS.md` и `config.portable.toml` в этом репозитории:

```bash
git clone https://github.com/v1nkore/codex-home.git
cd codex-home
./install.sh
```

Скрипт сохранит прежние `AGENTS.md`, `config.toml` и отличающиеся skills в `~/.codex/backups/`, затем установит файлы из репозитория. Он заменяет существующие `AGENTS.md` и `config.toml`. Если устройство уже было настроено, прежние правила можно вернуть из созданной копии; личные правила с другого устройства нужно переносить из отдельного приватного источника. Авторизация, подключения аккаунтов, сами плагины и локальные настройки не восстанавливаются этим скриптом. Проверьте модель и доступность плагинов в Codex, затем перезапустите приложение. Скрипт проверен на macOS; установка для Windows этим репозиторием пока не автоматизирована.

## Синхронизация изменений

Для синхронизации нужны Python 3 и `rsync`. Обновить переносимые настройки и skills без отправки:

```bash
./scripts/sync-from-home.sh
git status --short
git diff -- config.portable.toml skills
```

`AGENTS.md` редактируется отдельно: локальный глобальный файл может содержать личные пути и правила. Перед публикацией каждого нового skill проверьте его содержимое и лицензию. После просмотра изменений создайте коммит и отправьте его вручную:

```bash
git add config.portable.toml skills
git diff --cached --check
git diff --cached
git commit -m "Sync portable Codex settings"
git push
```

Проверить сценарии установки и синхронизации без изменения текущего Codex home:

```bash
./scripts/test-install-and-sync.sh
```

## Процесс разработки с агентами

[Стартовый набор](docs/agent-development/README.md) описывает последовательное внедрение практик для изменений с высоким риском: критерии до кода, карточку состояния задачи для передачи между сессиями, доказательства к diff, независимое ревью, проверки актуального commit и оценку качества ревьюера. Skill `critical-change-review` установлен через `install.sh` вместе с остальными skills. Шаблон проектного `AGENTS.md` из набора переносится в рабочий репозиторий только после адаптации к его командам, правилам и владельцам решений.

## Что намеренно исключено

В этом репозитории не хранятся:

- `auth.json`, токены и credentials;
- история чатов, диктовки, сессии и memories;
- SQLite-базы, логи, очереди и кэши;
- installation/device ID;
- абсолютные пути, project trust и локальная конфигурация MCP/runtime.
- личные правила маршрутизации по проектам из глобального `AGENTS.md`.

Эти данные секретны, эфемерны или привязаны к конкретному устройству. `.gitignore` ограничивает верхний уровень и отсекает распространённые локальные файлы внутри skills. Перед каждым push всё равно просматривайте новые файлы и diff.
